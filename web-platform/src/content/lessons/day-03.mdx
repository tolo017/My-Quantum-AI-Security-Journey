# Day 3: Networking Fundamentals I - TCP/IP Handshakes & DNS Zone Transfers

To defend or audit a digital environment, you must understand how data traverses the wire. If you cannot analyze standard network communication, you cannot identify malicious or anomalous data streams.

Today, we cover Layer 2, Layer 3, Layer 4, the 3-way TCP handshake, and how to execute a DNS Zone Transfer attack.

---

## 1. Deep Dive: The TCP/IP Model & Encapsulation

The networking stack is abstracted into standard layers. Each layer wraps the upper layer's data with its own header (Encapsulation).

```
+-----------------------------------+
|      THE NETWORK DATA WRAPPER     |
+-----------------------------------+
| [L2 MAC Header] [L3 IP] [L4 TCP]  | [Payload / App Data] | [L2 Trailer]
+-----------------------------------+
```

### The Key Layers:

#### Layer 2: Data Link Layer (Frames)
- **Protocol Data Unit:** Frame.
- **Addressing:** MAC Addresses (e.g., `00:1A:2B:3C:4D:5E`).
- **Function:** Local delivery on the same physical router switch. MAC addresses are hardcoded on your network interface card (NIC) and do not traverse internet gateways.

#### Layer 3: Network Layer (Packets)
- **Protocol Data Unit:** Packet.
- **Addressing:** IP Addresses (IPv4: `192.168.1.1`, IPv6: `fe80::1`).
- **Function:** Global routing across different subnets. Routers read the Destination IP Address in the IP header to send packets to external networks.

#### Layer 4: Transport Layer (Segments)
- **Protocol Data Unit:** Segment.
- **Addressing:** Port Numbers (e.g., Port `80` for HTTP, Port `443` for HTTPS, Port `22` for SSH).
- **Function:** Handles process-to-process delivery. Enforces communication rules:
  - **TCP (Transmission Control Protocol):** Connection-oriented. Establishes a connection with a 3-way handshake (`SYN` -> `SYN-ACK` -> `ACK`), guarantees packet order, and handles error correction.
  - **UDP (User Datagram Protocol):** Connectionless. Best-effort delivery without error correction or verification (ideal for streaming/DNS).

## 2. DNS: The Internet's Phone Book & Subdomain Enumeration

The **Domain Name System (DNS)** translates human-readable domain names (e.g., `bebasecurity.com`) into computer-readable IP addresses (e.g., `104.244.42.1`).

```
[Your Client] --- "Where is example.com?" ---> [Recursive DNS Resolver]
                                                     |
                                                     v
                                            [Root Server] (.)
                                                     |
                                                     v
                                            [TLD Server] (.com)
                                                     |
                                                     v
                                            [Authoritative Nameserver]
```

### DNS Record Types:
- **`A`:** Maps a domain to an IPv4 address.
- **`AAAA`:** Maps a domain to an IPv6 address.
- **`MX` (Mail Exchanger):** Directs email traffic to designated mail servers.
- **`TXT`:** Stores plain text notes (used for SPF/DKIM verification and proof of domain ownership).
- **`AXFR`:** Used for **DNS Zone Transfers** to replicate database records between primary and secondary DNS servers. If misconfigured, an attacker can download the entire DNS table, exposing all internal IP addresses and servers!

## 3. Field Portfolio Project: Active DNS Zone Transfer script (Python)

Let's write a real subdomain harvester script in Python using raw socket queries and the `dns` library. This is a primary OSINT and active reconnaissance script for mapping a target's internal landscape.

### Step 1: Install Python DNS Library
```bash
pip3 install dnspython
```

### Step 2: Create Your Python Recon Tool
Create a file named `dns_recon.py`:
```python
import dns.resolver
import dns.zone
import sys

def dns_recon(domain):
    print(f"[*] Starting DNS harvesting for: {domain}")

    # 1. Resolve Nameservers
    try:
        ns_answers = dns.resolver.resolve(domain, 'NS')
        servers = [str(rdata) for rdata in ns_answers]
        print(f"[+] Found Name Servers: {servers}")
    except Exception as e:
        print(f"[-] Could not resolve NS records: {e}")
        return

    # 2. Attempt AXFR Zone Transfer on each nameserver
    for server in servers:
        print(f"[*] Attempting Zone Transfer (AXFR) on: {server}")
        try:
            zone = dns.zone.from_xfr(dns.query.xfr(server, domain))
            print(f"[!] SUCCESS! Zone Transfer vulnerability detected!")
            for name, node in zone.nodes.items():
                print(f"    - {name}.{domain} -> {node.to_text(name)}")
        except Exception:
            print(f"[-] Zone transfer failed on {server} (Securely Configured)")

if __name__ == "__main__":
    target = sys.argv[1] if len(sys.argv) > 1 else "zonetransfer.me"
    dns_recon(target)
```

### Step 3: Test Your Recon Tool
Run the script against a safe, authorized testing server (`zonetransfer.me`):
```bash
python3 dns_recon.py zonetransfer.me
```

## 4. Hands-On Lab: Querying DNS via Command Line

Open your terminal and run DNS queries using the **`dig` (Domain Information Groper)** command-line tool:

```bash
# 1. Perform a basic DNS query for a domain
dig google.com

# 2. Query only the mail servers (MX records) for a domain
dig mx yahoo.com

# 3. Request a compact, text-only response for quick scripts
dig +short A google.com
```

Understanding how to construct raw DNS queries is crucial for mapping an organization’s public assets during reconnaissance (Active DNS Recon).
