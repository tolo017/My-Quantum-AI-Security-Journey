# Day 4: Networking Fundamentals II - HTTPS, SSH Tunnels & Packet Capture

Yesterday, we discussed the underlying transport layers of the internet. Today, we step up to Layer 7 (Application) and learn how to sniff, analyze, and intercept active network traffic on the wire, as well as bypass network firewalls using secure tunnels.

---

## 1. Deep Dive: HTTP, HTTPS, and TLS Encapsulation

When you visit a website, your browser sends **HTTP requests** (using commands like `GET`, `POST`, `PUT`, `DELETE`).

### HTTP vs. HTTPS
- **HTTP (Plaintext):** Communicates on Port `80`. All headers, cookies, passwords, and sessions are sent in raw, unencrypted text. Anyone sitting on your local Wi-Fi or router bridge can sniff these packets using Wireshark.
- **HTTPS (Secure):** Communicates on Port `443`. Wraps standard HTTP traffic inside an encrypted **TLS (Transport Layer Security)** tunnel.

```
+------------------------------+
|       HTTPS WRAPPING         |
+------------------------------+
| HTTP Data (GET /index.html)  |
|               v              |
|   TLS Encryption Layer       | <--- Secures sessions & data
|               v              |
| TCP Segment (Port 443)       |
+------------------------------+
```

### The TLS Handshake
To establish a secure connection, your browser and the webserver negotiate encryption keys:
1. **Client Hello:** Browser sends supported TLS versions and encryption algorithms (Cipher Suites).
2. **Server Hello:** Server selects the Cipher Suite and responds with its **SSL/TLS Certificate** containing its Public Key.
3. **Key Exchange:** The browser verifies the certificate with its trusted Root Authorities, generates a shared session key, encrypts it with the server's public key, and sends it back.
4. **Encrypted Tunnel Established:** Both sides use the shared session key to run symmetric-key encryption for all subsequent requests.

## 2. SSH Tunnels & Port Forwarding

**SSH (Secure Shell)** on Port `22` provides remote terminal access encrypted by asymmetric keys. However, it can also be used to bypass restrictive firewalls by routing traffic through secure encrypted pipes:

- **Local Port Forwarding (`-L`):** Forwards a local host port to a remote server port (e.g., forwarding local 8080 to an internal database port 3306 on a remote server).
- **Remote Port Forwarding (`-R`):** Forwards a remote server port back to your local port, exposing a local service to the internet.
- **Dynamic Port Forwarding (`-D`):** Converts your SSH client into a secure SOCKS5 proxy server. Any browser or tool pointed at this SOCKS proxy routes its traffic directly through the encrypted SSH server.

```bash
# Set up a secure Dynamic SOCKS5 Proxy on port 9050
ssh -D 9050 -N -f user@remote-jump-box
```

## 3. Wireshark & Tshark BPF Packet Capture

**Wireshark** is a GUI-based open-source packet analyzer. For terminal-based headless scripting, we use its CLI counterpart: **`tshark`**.

To capture specific packets efficiently, we use **Berkeley Packet Filters (BPF)**:
- Filter for specific IP: `host 192.168.1.1`
- Filter for protocol and port: `tcp port 443`
- Filter excluding a protocol: `not arp`

## 4. Field Portfolio Project: SOCKS5 Proxy Pivot & Traffic Analysis

Let's simulate a network engineering and analysis scenario:
1. Set up a secure SOCKS5 pivot tunnel on your workstation.
2. Intercept and capture local loopback packet exchanges using `tshark` with advanced BPF display filters.

### Step 1: Establish SOCKS5 Dynamic Proxy
Let's spin up a local SSH-based proxy server. If you don't have a remote host, you can proxy through your local host loopback:
```bash
ssh -D 1080 -N -f localhost
```
*(Verify your SOCKS5 proxy is listening on port 1080 using `ss -tuln | grep 1080`)*

### Step 2: Capture SOCKS/SSH Protocol Traffic
Open another terminal pane and run `tshark` in capture mode, restricting it only to local TCP loopback traffic on port 1080:
```bash
# Capture 10 packets and print basic summary fields
sudo tshark -i lo -c 10 -f "tcp port 1080"
```

### Step 3: Parse and View Specific Fields
Use display filters to extract specific payload headers (such as raw destination IP and TCP sequence counts):
```bash
sudo tshark -i lo -c 5 -f "tcp port 1080" -T fields -e frame.number -e ip.dst -e tcp.len
```

This portfolio exercise teaches you how to construct, route, and audit secure cryptographic tunnels on modern enterprise networks!

## 5. Hands-On Lab: Capturing Local Bridge Packets

Let's verify how networks communicate. We will run a quick packet sniff on your terminal using `tshark`:

```bash
# 1. Install tshark if not present
sudo apt install -y tshark

# 2. List available network interfaces
tshark -D

# 3. Capture exactly 5 packets traversing your active interface (e.g., eth0 or wlan0)
sudo tshark -c 5
```
