# Day 4: Networking Fundamentals II - HTTPS, SSH & Packet Capture

Yesterday, we discussed the underlying transport layers of the internet. Today, we step up to Layer 7 (Application) and learn how to sniff, analyze, and intercept active network traffic on the wire.

---

## 1. Deep Dive: HTTP, HTTPS, and TLS Encapuslation

When you visit a website, your browser sends **HTTP requests** (using commands like `GET`, `POST`, `PUT`, `DELETE`).

### HTTP vs. HTTPS
- **HTTP (Plaintext):** Communicates on Port `80`. All headers, cookies, passwords, and sessions are sent in raw, unencrypted text. Anyone sitting on your local Wi-Fi or router bridge can sniff these packets using Wireshark.
- **HTTPS (Secure):** Communicates on Port `443`. Wraps standard HTTP traffic inside an encrypted **TLS (Transport Layer Security)** tunnel.

```
+------------------------------+
|       HTTPS WRAPPING         |
+------------------------------+
| HTTP Data (GET /index.html)  |
|               v              |
|   TLS Encryption Layer       | <--- Secures sessions & data
|               v              |
| TCP Segment (Port 443)       |
+------------------------------+
```

### The TLS Handshake (Simplified)
To establish a secure connection, your browser and the webserver negotiate encryption keys:
1. **Client Hello:** Browser sends supported TLS versions and encryption algorithms (Cipher Suites).
2. **Server Hello:** Server selects the Cipher Suite and responds with its **SSL/TLS Certificate** containing its Public Key.
3. **Key Exchange:** The browser verifies the certificate with its trusted Root Authorities, generates a shared session key, encrypts it with the server's public key, and sends it back.
4. **Encrypted Tunnel Established:** Both sides use the shared session key to run symmetric-key encryption for all subsequent requests.

## 2. SSH: Cryptographically Secure Shell

**SSH (Secure Shell)** on Port `22` replaced unencrypted protocols like Telnet and rlogin. It provides remote terminal access encrypted by asymmetric keys.

### Authentication Methods:
- **Password Authentication:** Susceptible to brute-force and dictionary attacks.
- **Key-Based Authentication (Best Practice):** Uses a cryptographic keypair. You upload your public key (`~/.ssh/id_rsa.pub`) to the target server's `authorized_keys` file. When you connect, the server challenges you to sign a message using your private key (`~/.ssh/id_rsa`), validating your identity without sending credentials over the network.

## 3. Wireshark: Sniffing Packets on the Wire

**Wireshark** is a GUI-based open-source packet analyzer. In containerized labs, we use it to inspect bridge traffic.
For terminal-based headless scripting, we use its CLI counterpart: **`tshark`**.

### Capture Filters vs. Display Filters:
- **Capture Filters (BPF Syntax):** Restricts what gets written to the disk (e.g., `tcp port 80`).
- **Display Filters:** Filters the captured packets currently shown on the screen (e.g., `ip.src == 192.168.1.100 && http.request.method == "POST"`).

## 4. Hands-On Lab: Capturing Local Bridge Packets

Let's verify how networks communicate. We will run a quick packet sniff on your terminal using `tshark`:

```bash
# 1. Install tshark if not present
sudo apt install -y tshark

# 2. List available network interfaces
tshark -D

# 3. Capture exactly 5 packets traversing your active interface (e.g., eth0 or wlan0)
sudo tshark -c 5
```
